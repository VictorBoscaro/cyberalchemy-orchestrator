# APT-P002 — Topic drift across an activation

## Claim under test

Capturing an initial and a close topic snapshot reveals material information acquired or reframed
during work. If close snapshots are almost always byte-identical or merely paraphrastic, the extra
capture is ritual telemetry and should not be the default.

## Method

1. Use one agent execution for each of the 12 shared fixtures.
2. The harness captures four disjoint inputs: system-derived `profile_field`, system-derived
   `profile_tags`, parent-proposed `dispatch_topic_tags`, and the agent's isolated emitted terms.
3. The agent emits once after reading the task (`initial`) and once immediately before its terminal
   answer (`close`). It may emit `context_shift` only if it declares that the material subject changed.
4. Compute:

   - prediction divergence only over IDs resolved under the same registry version:
     `D_pred = 1 - J(dispatch_resolved_ids, initial_resolved_ids)`;
   - free-term execution drift: `D_free = 1 - J(initial_free_terms, close_free_terms)`;
   - resolved execution drift: `D_resolved = 1 - J(initial_resolved_ids, close_resolved_ids)`;
   - close novelty, reported separately for free terms and resolved IDs:
     `N_close = |close - initial| / max(1, |close|)`;
   - content duplicate rate: fraction of close snapshots whose `topic_content_digest` equals the
     initial value. This digest covers only the sorted canonical free-term set and sorted resolved-ID
     set, never trigger, timestamps, sequence or other envelope fields.

5. Preserve additions and removals as directional evidence. Do not collapse both into one score, mix
   free terms with IDs, or include profile field/tags in these Jaccards.

## Preregistered decision

- Keep `initial + close` by default only if at least 4/12 fixtures add or remove two or more resolved
  tag IDs and the content duplicate rate is below 50%. Free-term deltas are reported separately and
  may motivate a versioned follow-up, but do not control this gate.
- If fewer than 4 fixtures change materially or duplicate rate is at least 75%, default to one close
  snapshot per activation; retain initial capture only for experiments or high-stakes protocols.
- Results between those bands remain unresolved and require a larger run before choosing cadence.

## Falsifiers and invalid runs

- Initial snapshot occurs after substantive tool use.
- Close snapshot is generated by the parent from the final answer rather than emitted by the worker.
- Static profile tags are copied into observed tags and counted as runtime discovery.
- Missing close emissions are treated as empty sets instead of capture failures.

## Output

Pinned initial/close pairs, directional deltas, aggregate metrics and the cadence decision. This probe
does not judge whether the task result was correct.
