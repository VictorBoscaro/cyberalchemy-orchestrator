Where recovery and transport adapters fit in RWO

RWO is the Recursive Work Orchestrator. ARE is the optional Agent Reasoning Engine. Recovery classifies one admitted situation before ordinary RWO routing. Transport adapters move canonical commands and event candidates, but they report scoped observations rather than choosing acceptance, retry, authority, or effects.

Current reality: the graph contains no recovery nodes, and the transport-neutral adapter contract remains Candidate-2 design evidence. Proposed integration: attach the recovery overlay to current RWO anchors and keep command delivery, event ingress, journal acceptance, adapter admission, Work recovery, and effect reconciliation as separate boundaries.

Layer 3 · transport truth boundary

Adapters move messages; owners decide what they mean

components.transport-neutral-adapter + flow.delivery-to-recovery
Plain model: every transport implements the same separation, not the same guarantees. Canonical identity and closed observation names are shared. Durability, redelivery, acknowledgement, ordering, replay, flow control, fan-out, and settlement are exact capabilities admitted per implementation and configuration.
View-local Candidate-2

Inside the transport adapter

  • CommandDeliveryPort sends an already admitted canonical command and returns a scoped delivery observation.
  • EventIngressPort converts transport input into a canonical event candidate plus transport evidence.
  • TransportDeliveryAttempt changes on redelivery; logical message identity and canonical digest do not.
  • The adapter cannot mint a Work Attempt, choose retry, accept history, or authorize an effect.
Independent boundaries

Outside the transport adapter

  • JournalAcceptancePort returns accepted record, identical duplicate, conflict, or rejection.
  • Admission owner binds exact implementation and configuration digests, manifest, requirements, current conformance evidence, owner, and validity epoch.
  • RWO recovery alone may choose same-message retry or create a new Work Attempt from accepted history.
  • Exact-effect owner reconciles an unknown external-effect outcome.
  1. Preserve identity.
    Canonical bytes, logical message ID, Work Run, and Work Attempt remain stable across delivery attempts.
  2. Move or receive.
    Command delivery and event ingress stay distinct even when one transport carries both.
  3. Report.
    The adapter emits one closed, scoped observation such as accepted_by_transport, outcome_unknown, redelivered, or flow_controlled.
  4. Accept history.
    The journal independently accepts, deduplicates, conflicts, or rejects the candidate.
  5. Decide treatment.
    Only accepted evidence reaches RWO recovery or effect-owner reconciliation.

Manifest = claim

Closed capability atoms with exact scopes, limitations, prohibitions, and implementation/configuration digests.

Requirements = need

The route and message class state which durability, ordering, acknowledgement, replay, fan-out, pressure, and settlement behavior they require.

Admission = evidence-bound fit

A current owner-issued conformance receipt must bind the exact manifest/requirements tuple. Profile names and self-declaration are insufficient.

“Retry” spans seven distinct situations

SituationOwner and treatment
ReconnectAdapter creates a connection epoch; no Work state changes.

Reader terms

Reader terms and why it matters

RWO
Structural coordinator for typed work graphs and accepted history. It does not own domain meaning.
Recovery case
One admitted, typed situation. It carries facts; it does not itself perform treatment.
Recovery frontier
Journal-owned selection of at most one actionable overlapping trigger.
ARE
Optional reasoning evidence after admission. Never a route, disposition, or authority owner.
Atomic acceptance
All-or-nothing recheck and append. Any changed input means no mutation and case rebuild.
Candidate delta
A proposed ontology mapping. It is not the current graph and carries no promotion effect.
Delivery observation
A scoped transport statement such as provider accepted, outcome unknown, or redelivered. It is not accepted Work history.
Adapter admission
A pass or block for one exact implementation/configuration and current conformance evidence. It grants no authority.
Redelivery
The same canonical message in a new transport attempt. It is not a new Work Attempt, replay, or effect retry.
