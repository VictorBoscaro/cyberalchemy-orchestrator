07 · evidence boundary

Where this report is weakest, stated plainly.

The strip costs more vertical space than any other element in this report, and it answers when — the question a reader needs least. Nobody picking up a day report is primarily asking what time things happened; they are asking what was done and what is still open. The strip earns its space here only because when happens to be the carrier of this particular day's defect: the record cutoff at 17:04 and the volume spike at 04:49 are the same fact seen from two lanes, and no table makes that adjacency as fast. On a day whose record and change were aligned, the same figure would be pure cost. Read it once, then read the prose.

Ranking by change volume cannot tell a build artifact from a judgement. The clearest proof is inside the day's largest commit. 187b8b1 carries 7,657 insertions, of which 2,098 are lines of a PDF that git chose to diff as text, and 1,337 are a frozen source snapshot of a file committed 80 seconds earlier in the previous commit. That is 3,435 insertions — 44.9 % of the largest commit in the block — that are machine output or duplicated content. Meanwhile 51a5e8a ranks second-to-last at 29 insertions and contains the correction that re-diagnosed a whole class of failure from a configuration problem to a host binary defect, and 7014cdf ranks last at zero and discharged a recorded obligation. The ranking in this report orders by size, and size is not importance. Where the two conflict, the prose says so; the ordering does not.
