# Assay S0 — forward research → discovery → first functional gzip build

## Summary

This session took the Assay tool (`document-information-estimator`) in `internal-tools/research` from a pre-PoC brief to a first functional, TESTED build, driven as an autonomous multi-dispatch chain the owner authorized (delegating per-dispatch confirm to the main thread). A forward-research dispatch (explorers Xiao⊥Liu⊥Shannon → synthesizer → skeptics Tetlock/precedent ⊥ Gigerenzer/definitional, plus one feedback re-sweep) returned an all-GO verdict: the `L(unit|corpus)` kernel is build-from-owned (wrap Microsoft `llmlingua.get_ppl`), the behavioral-equivalence-on-instructions eval is a genuine build-from-owned gap (ACON/CoACT/AGORA are adjacent method-donors, not owners), P-GUARD is a precedent-clean novel-attempt, and "self-corpus prolixity" is a re-skin application, not a distinct object. A `domainspec-discovery-orchestrator` planned the discovery but hit a real runtime wall (read-only, no Write/Task), so the main thread executed its plan: a writer + two-reviewer dispatch produced `assay-discovery.md`, on whose acceptance two reviewer gaps were fixed (GAP-B: gate the acceptance test on window-safe `pair_B` instead of 32 KB-window-limited full-corpus `B`; GAP-A: add `TIGHTEN_DELTA_TAU`). A coder then built S0 — a gzip-only, confound-guarded redundancy audit over the 69 `.claude/skills/*/SKILL.md` — which passes its acceptance gate (body-identical pairs score `pair_B≈0`), is stdlib-only and read-only over the corpus. Code review surfaced OQ-AS6: gzip cannot trustworthily populate the P-GUARD `protected` column, because the absolute `NEARDUP_TAU` over-triggers when `A(u)≈τ` and genuine cross-skill repetition is mostly paraphrase (the documented gzip blind spot). At the owner's instruction to fix open items, a calibration pass set a scale-invariant companion `pair_B ≤ k·A(u)` against a labelled 10-pair set, defaulting `DEFAULT_NEARDUP_K=0.65` (mid-plateau [0.635, 0.69]), cutting `protected` 12→5 (six of eight artifacts removed) while keeping the acceptance gate green; an independent reviewer judged it SOUND-WITH-NOTES (anti-overfit) with one factual nit that was corrected. Everything model-based (S1 neighbours, S2 LM kernel, the behavioral falsifier, forks F1–F4) stays deferred by design — expansion work the owner gated behind future specs. Nothing was committed; the deliverables are the S0 code, the discovery, the forward-research artifacts, and two closed ledger dispatches.

## Open questions

- **OQ-AS6** — Can gzip alone ever separate deliberate rule-restatement from shared generator-template boilerplate (the `discovery-to-inventory` / `implementation-readiness` stub class) and paraphrase repetition, or is a trustworthy P-GUARD `protected` column provably a semantic judgment only the LM kernel can make? Conjecture: an intrinsic gzip ceiling, not a threshold-tuning problem — calibration cut the `A≈τ` artifact but could not recover the paraphrase/template cases.
