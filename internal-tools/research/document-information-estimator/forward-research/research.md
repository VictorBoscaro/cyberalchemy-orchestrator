## Explorer 1 — Xiao, Guangxuan (angle: external ML/compression corpus, operator-ownership of L(unit|corpus))

## Findings: Operator-ownership of L(unit|corpus) — LLMLingua family

### (a) Strongest owner candidate
Microsoft's `llmlingua` package (`PromptCompressor` class, `microsoft/LLMLingua` GitHub repo) owns a directly reusable, public implementation — confirmed by reading source (`llmlingua/prompt_compressor.py`): `get_ppl(text, granularity, condition_mode, condition_pos_id)` runs a causal LM forward pass, computes per-token cross-entropy via CrossEntropyLoss(reduction="none"), can mask loss to only tokens after a given position. `get_condition_ppl(text, question, condition_in_question)` concatenates question+text and masks so only target segment contributes. Setting question=<corpus>, text=<unit>, condition_in_question="before" yields exactly per-token cross-entropy of unit conditioned on corpus — Assay's L(unit|corpus) off the shelf. This is the engine under LongLLMLingua (arXiv 2310.06839): contrastive perplexity s_i = PPL(x_i|x_<i) − PPL(x_i|question,x_<i) = conditional pointwise mutual information. Base LM: LLaMA-2-7B-Chat. Earlier Selective Context (Li et al. 2023) = pure self-information −log p(token|context), no question — closer mathematical ancestor; llmlingua get_ppl is closer engineering ancestor (maintained, pip-installable). Coverage HIGH for the compute primitive — a checked callable signature, not an inferred paper claim.

### (b) Wrap-vs-build verdict
WRAP the primitive; BUILD the corpus-serialization + aggregation layer. Gaps forcing build: (1) causal single-prefix conditioning only — corpus must be a linear prefix in one attention window (hard truncation at max_position_embeddings); scattered instruction files need Assay's own serialization/ordering/chunking. (2) Runtime/hosting cost — loads and runs a real causal LM locally, not an API call. (3) No unit-level aggregation or redundancy score — returns raw per-token loss; rolling into unit-level normalized marginal-information + threshold is build work. (4) No gzip-first confound guard — unaddressed upstream. Net: build-from-owned WIN. (Aside: LLMLingua2 [2024] uses a distilled BERT token-classifier — different supervised primitive, not applicable.)

### (c) Instruction-redundancy-for-agents prior art
"What Should a Skill Remember?..." (arXiv 2606.09421) — cost-aware skill rewriting, preserves "sparse operational anchors"; on-topic but functional categories not an info-theoretic metric (title/abstract only, lower-confidence). Claude Code 2.0 system-prompt changes (MUST→should, removed absorbed convention blocks) — concrete practitioner instance of prolixity-of-own-instructions. "Many-Tier Instruction Hierarchy" (arXiv 2604.09443) — adjacent, not redundancy. No paper formalizes "redundancy of an instruction given the rest of an agent's instruction corpus" as L(unit|corpus) on instructions specifically — LLMLingua/Selective-Context is document/RAG-focused. Applying the wrapped primitive to self-instruction-corpora is a genuine non-owned application on an owned kernel.

## Explorer 2 — Liu, Nelson (angle: external NLP/faithfulness corpus, behavioral-equivalence eval ownership/gap)

## Findings — Behavioral-equivalence evaluation of compressed prompts
(a) SOTA, descending relevance: 1. "Understanding and Improving Information Preservation in Prompt Compression for LLMs" (Amazon Science, EMNLP 2025 Findings, arXiv:2503.19114) — most systematic eval framework; scores LLMLingua/xRAG/PISCO on downstream EM/BERTScore, FABLES-style claim-faithfulness, reconstruction retention. 2. "Separating Constraint Compliance from Semantic Accuracy..." (arXiv:2512.17920) — on-topic name but single-turn format/style constraint adherence; explicitly NOT multi-step/agent decision-making, no safety-guardrail tightening. 3. SkillReducer (arXiv:2603.29919) — optimizes LLM-agent skill files for tokens, LLM-judged faithfulness + task pass-rate (86.0%, +2.8%, less-is-more); closest to agent-behavior preservation but single-skill success, not trajectory identity. 4. Tool-Schema Compression TSCG (arXiv:2605.26165) — EM task success at fixed budgets, not trajectory-level tool-choice identity. 5. AgentEvals/LangSmith trajectory evaluation — right primitive (strict/superset/subset trajectory matching, tool-call functional-equivalence judging) but general agent-eval, NOT instrumented for pre- vs post-compression prompt trajectories. 6. DAC (arXiv:2507.11942) + Prompt Compression Survey (arXiv:2410.12388) — field standard = downstream benchmark score, behavior/decision identity not in the eval vocabulary.
(b) Owned or gap? Genuine gap (build-from-owned, not kill). Closest owners: Amazon info-preservation framework (eval methodology half) + SkillReducer (agentic half). Neither measures: same tool selected, same arguments, same gate/pass-fail, same multi-step trajectory shape, before vs after instructions are compressed. Agent-trajectory equivalence under compression is NOT owned externally — intersection of two separately-covered areas no paper has fused. Build on Amazon fidelity metrics + AgentEvals trajectory-matching, not from scratch.
(c) P-GUARD? No general principle stated this way. SecurityLingua (arXiv:2506.12707) — specific security-aware compressor technique, not a general shrink→tighten principle. A search-synthesized claim that medium-length prompts (20-35 words) maximize constraint violations (unverified, not load-bearing). No paper states P-GUARD as explicit design principle — appears original.
