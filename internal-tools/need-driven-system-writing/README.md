# Need-Driven System Writing

## What this folder is

This folder is the working laboratory behind the repository-local
`write-need-driven-documents` skill. It preserves investigations, disagreements, negative results,
and candidate ideas that should not automatically become writing rules.

The invocable skill lives at
[`../../.codex/skills/write-need-driven-documents/SKILL.md`](../../.codex/skills/write-need-driven-documents/SKILL.md).
The `.agents` copy is a synchronized runtime mirror, not a second editorial authority.

## Current boundary

The installed skill is intentionally small and must be invoked explicitly. It is for materially
composing or restructuring reader-facing explanations whose main difficulty is introducing
unfamiliar ideas in an intelligible order. It is not the default for ordinary answers, summaries,
specifications, research reports, plans, reference material, or surface copyediting.

Its current core is provisional and scoped. It conducts a reader toward a defined change in
understanding, prepares an idea before depending on it, explains relations instead of presenting
collections, introduces names after their referents are understood, keeps claims within their
support, and removes demands on attention that produce no useful return.

Lists and tables are avoided by default. They are appropriate only when independent scanning or
exact comparison is the reader's real need. A sequence must not substitute for an explanation of
why its parts belong together.

## Authority and use

The skill is the operational instruction. This laboratory is evidence and design history. Nothing
under `robot-talks/` silently changes the skill, and old reports may cite earlier versions or line
numbers. Treat those citations as historical evidence rather than current operating guidance.

Invoke the skill in a chat with `$write-need-driven-documents`. Its UI metadata disables implicit
invocation so that the method is used deliberately and with parsimony.

## Status

The skill and its runtime mirror validate successfully. They are currently repository-local
working-tree additions and have not yet been committed. The next useful evidence should come from
small, explicit uses on real documents. Revise the skill only when those uses expose a repeatable
failure; keep preferences and untested theory in this laboratory.
