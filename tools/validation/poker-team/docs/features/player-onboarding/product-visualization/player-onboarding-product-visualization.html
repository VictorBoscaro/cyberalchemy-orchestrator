Journey 1: Candidate Guided Intake

Acquire + Qualify CAP-01 CAP-02 CAP-03

Candidate journey from opening onboarding content through compliant, deduplicated submission persistence.

Journey Sequence

  1. Open onboarding and load grouped rules screens.
  2. Read rules and register acceptance.
  3. Unlock candidate form only after acceptance.
  4. Submit candidate payload for validation and duplicate checks.
  5. Persist CandidateApplication with SUBMITTED state.

Integrated Capability Outcome

CAP-01: clear rules-first flow composition.

CAP-02: hard compliance gate on rules + LGPD.

CAP-03: qualified, deduplicated persisted application.

Journey 2: Reviewer Controlled Decision

Decide CAP-04

Authenticated operations and leadership users pull backlog entries, inspect details, and perform deterministic approve/reject review decisions.

Journey Sequence

  1. Open admin review page and list candidates.
  2. Select one application and open full detail.
  3. Submit APPROVE or REJECT decision.
  4. Persist final status plus review metadata.
  5. Emit CandidateApplicationReviewed event.

Integrated Capability Outcome

CAP-04: reviewer actions are permissioned, state-safe, and auditable.

Final transitions: SUBMITTED|UNDER_REVIEW -> APPROVED|REJECTED

Operations and Detailed Description
Operation Description Auth Model Output
GET /admin/onboarding/candidates (ListCandidateApplications) Lists candidate backlog with optional status and pagination filters. Bearer + player-onboarding.review.listCandidates { items[], page, limit, total }
GET /admin/onboarding/candidates/{id} (GetCandidateApplicationById) Fetches complete candidate payload for manual decision context. Bearer + player-onboarding.review.getCandidateDetail { candidateApplication }
PATCH /onboarding/candidates/{id}/review (ReviewCandidateApplication) Validates authorization, state, and decision semantics; persists final status and review metadata. Bearer + player-onboarding.review.evaluateApplication { id, status, reviewedAt }

Journey 3: Approved Handoff and Funnel Optimization

Activate + Optimize CAP-05 CAP-06

Approved decisions must produce deterministic handoff payloads for player-management, while telemetry continuously validates funnel quality and policy safety.

Journey Sequence

  1. Reviewer approves candidate in Journey 2.
  2. System emits CandidateApplicationReviewed with final status.
  3. Downstream player-management consumes approved intake payload.
  4. Observability tracks conversion, latency, and rule-risk signals.
  5. Product and operations tune policy/UX based on trend and alert feedback.

Integrated Capability Outcome

CAP-05: deterministic handoff quality for downstream activation.

CAP-06: measurable funnel health and guardrail monitoring.
