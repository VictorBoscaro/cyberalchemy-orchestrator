# Post-implementation review — ConfirmedCorpusManifest fixture

## Verdict

**BLOCK**

The fixture correctly materializes and compares the host-owned manifest, is deterministic in the
current repository state, passes its 12 tests, works from a nested working directory when
`--repo-root` is supplied, and performs no application writes. It does not yet close R1 because one
path-binding check and the writer-owned Inventory projection/equivalence contract are missing.

All fixture files were inspected. The schema accepts the generated manifest under Draft 2020-12.

so they provide a useful check independent of the parser; they are not merely regenerated by the
code under test.

## Findings

### 1. The verifier does not bind the physical input file to `confirmed_manifest_path`

- **File:** `confirmed_corpus_manifest.py`
- **Evidence:** `verify()` computes `expected = materialize(root, manifest["confirmed_manifest_path"])`,
  while the CLI separately opens `args.manifest` using `with args.manifest.open(...)`. No comparison
  connects those two paths.
- **Conflicting contract:** the README says the contract binds “its intended exact
  repository-relative output path”, and `08-execution-sheet-reaudit.md` requires “the manifest
  schema/version and exact resolved path”.
- **Severity:** **MAJOR**
- **Verified reproduction:** canonical bytes declaring the allowlisted run path were written to a
  different temporary file outside the repository and passed `verify()`, producing
  `WRONG_ACTUAL_MANIFEST_PATH_ACCEPTED`.
- **Proposed fix:** pass the physical manifest path into verification, resolve it against the repo
  root, and require exact equality with the normalized `confirmed_manifest_path`; add negative tests
  for a correct manifest at the wrong in-repo and out-of-repo locations.

### 2. The required writer-owned Inventory projection and equivalence algorithm are absent

- **Files:** `README.md`, `confirmed_corpus_manifest.py`
- **Evidence:** the README narrows the fixture to the “host-owned, pre-write manifest”; the
  implementation only materializes and verifies that same manifest. It has no serializer,
  projection function, schema, verifier, or golden fixture for
  `.arcanum/inventory/raw/d1-lens-use-corpus.manifest.json`.
- **Governing requirement:** `04-execution-sheet.md` says the writer-owned file is a
  “Deterministic Inventory projection of `ConfirmedCorpusManifest`; ... Auditor proves declared
  projection equivalence.” `08-execution-sheet-reaudit.md` requires “canonical serialization or a
  field-level equivalence algorithm for the Inventory projection”.
- **Severity:** **MAJOR**
- **Why this is not a wording issue:** equality between a host manifest and a fresh reconstruction
  of that host manifest does not decide equivalence of the distinct writer-owned projection. T11
  therefore remains mechanically indeterminate.
- **Proposed fix:** define the exact projection schema/mapping, implement a read-only equivalence
  verifier, and add positive plus omitted/extra/reordered/semantically altered projection fixtures.

## Checks that survived attack

- Source bytes, sizes, repository revision, semantic-authority identity, and external-row identity
  are recomputed rather than trusted from the manifest under test.
- The 22 rows are compared row-for-row between `04` and the external source, and actual source hashes
  are checked against the frozen table.
- Source/control omission, addition, reordering, and semantic changes are rejected by the current
  tests.
- Canonical JSON is key-sorted, compact, UTF-8-compatible, and newline-terminated.
- No materializer/verifier code path writes a manifest or Inventory content; materialization emits
  only stdout. Python bytecode was disabled during review tests.
- Explicit `--repo-root` avoids CWD drift in the documented invocation shape; a nested-CWD probe
  passed.

## Recheck — 2026-08-13

**Verdict: PASS.** Both previously blocking findings are closed by the corrected fixture.

- The complete suite reports `Ran 18 tests ... OK` with Python bytecode writes disabled.
- Both JSON Schemas pass Draft 2020-12 schema checks and validate their freshly materialized host
  manifest and Inventory projection instances.
- The original physical-path substitution attack was repeated through the real CLI using canonical
  manifest bytes in a temporary file outside the repository. Verification exited non-zero with
  `BLOCK/manifest-path-outside-repository`. The in-repository wrong-path negative also passes in the
  18-test suite with `BLOCK/CONFIRMED_MANIFEST_PATH_DIVERGENCE`.
- The Inventory projection binds the host manifest by exact `path`, `sha256`, `size`, and `revision`;
  independent mutation of each field was rejected with
  `BLOCK/INVENTORY_PROJECTION_DIVERGENCE`.
- The denominator is exactly `{22 sources, 8 controls, 176 cells}`. Independent mutation of each
  denominator field was rejected with `BLOCK/inventory-projection-denominator`.
- Exact projection equivalence accepted the deterministic positive instance and rejected omission,
  addition, source reordering, and semantic control mutation with typed projection failures.
- A before/after SHA-256 snapshot of the 22 frozen sources, `.arcanum/inventory/`, and the fixture's
  implementation, tests, schemas, and README remained identical across the independent probes (39
  scoped files). No manifest or Inventory artifact was written.

The recheck supports only R1 closure: it does not authorize an exact run or imply that later
readiness requirements are satisfied.
