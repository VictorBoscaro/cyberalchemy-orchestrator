# Frozen explorer evidence

This file freezes the four explorer returns used by the synthesis stage. It is an evidence input, not an adoption decision. `Not found` always means not evidenced in the named public surfaces at the pinned revision; it does not mean universal absence. GitHub activity numbers are temporal indicators, not proof of maturity, quality, or adoption.

Evidence labels: **DA** documentation assertion; **IW** implementation witness; **TW** repository test witness; **EO** observation executed by an explorer.

- Pinned revision: [`ebe165b44be023db07fa54d443c4284f4ac60afa`](https://github.com/boundflow/boundflow/commit/ebe165b44be023db07fa54d443c4284f4ac60afa), public preview/pre-1.0, SDK `0.5.0`; backend Apache-2.0, Python SDK MIT.

- Product layer: distributed Go/Postgres control plane plus Python data plane. Server owns workflows/policies/approvals/tenants; scheduler owns partitions, queues and lifecycle policies; workers stream jobs over gRPC; operator-held workers keep inference keys in the operator environment.
- Workflow witness: versioned workflow activation → invocation/customer request → queue/coalesce/backpressure → persisted job → worker lease → `Complete`, `Next`, `AwaitApproval` or `AwaitInput` → persisted state/context/metrics → resumed gate → lifecycle policy decision. Creation/invocation/scheduling are in [`lifecycle.go`](https://github.com/boundflow/boundflow/blob/ebe165b44be023db07fa54d443c4284f4ac60afa/internal/service/lifecycle.go#L170-L280); lease acquisition/renewal in [`job.go`](https://github.com/boundflow/boundflow/blob/ebe165b44be023db07fa54d443c4284f4ac60afa/internal/storage/postgres/job.go#L25-L119); branch/gate construction in [`worker.py`](https://github.com/boundflow/boundflow/blob/ebe165b44be023db07fa54d443c4284f4ac60afa/sdk/python/boundflow/worker.py#L745-L833); approval/rejection/timeout tests in [`test_approval_gate.py`](https://github.com/boundflow/boundflow/blob/ebe165b44be023db07fa54d443c4284f4ac60afa/sdk/python/tests/test_approval_gate.py).
- Supported capabilities: persistent distributed execution, leases, opt-in recovery, approval/input gates, numerical runtime governance, adaptive agent/workflow policies, rollback, multi-tenancy/API keys, queue/coalesce/backpressure, typed governance audit and OTel traces.
- Contrary evidence: recovery is at-least-once between operation checkpoints; the same operation may run twice after worker death and side effects require idempotency ([TW](https://github.com/boundflow/boundflow/blob/ebe165b44be023db07fa54d443c4284f4ac60afa/sdk/python/tests/test_resumable_workflow.py)). `max_cost_usd` is not a hard mathematical cap because authorization uses already observed cost and the actual cost arrives later ([IW](https://github.com/boundflow/boundflow/blob/ebe165b44be023db07fa54d443c4284f4ac60afa/sdk/python/boundflow/governed.py#L376-L423)). Approval/input decisions are made before a best-effort audit append; audit failure is logged without rollback or retry ([IW](https://github.com/boundflow/boundflow/blob/ebe165b44be023db07fa54d443c4284f4ac60afa/internal/service/lifecycle.go#L603-L704)). OTel is deliberately best-effort and is not mandatory evidence.
- Additional territory: scheduler partitions, worker recovery, persistent mid-workflow gates, backpressure, numerical governance, automated policy/rollback, multi-tenancy and managed-cloud operation.
- Candidate mechanisms: correlate governance audit and execution telemetry while keeping them distinct (**adopt concept, strengthen atomicity**); persistent gates with branch/timeout (**adapt**); leases and reconciliation (**investigate for remote runtime**); base/effective policy plus triggering rule (**adapt as evidence model**); hierarchical OTel spans (**adapt with redaction**); declared enforcement levels and warning when a limit is unenforced (**adapt**).

## Cyberalchemy-relative synthesis constraints

Across the eight inspected revisions, Cyberalchemy's best-supported differentiators are not feature-count claims. They are the repository-local, separately validated and journaled semantics around: an exact confirmed dispatch; one sanctioned append path; open/close lifecycle; immutable capability-route and prompt/manifest digests; parent-seat binding; launch authorization that can fail closed; explicit roles/topology/final approval; evidence standing (`built`, `local-pilot`, `proposed`, `open`, `contested`); and the objective of preserving the relation from work to objective, decision/authority and evidence.

None of the eight repositories was shown to implement that whole combination. This is not a novelty claim: several mechanisms have close precedents, especially OMA context lineage and structural receipts, BoundFlow governance audit, Temporal durable child workflows, Chorus durable identity/session separation, and Agent Fleet evidence contracts. Conversely, Cyberalchemy does not evidence the production execution substrate, full operational UI, remote worker scheduling, mid-turn recovery, model/tool gateway, budget accounting, multi-tenancy or SDLC application surfaces implemented by several comparables. Many of these are intentional or undecided product boundaries, not demonstrated deficiencies.

Cross-cutting high-value candidates for synthesis:

1. **Plan artifact/replay plus frozen resume context** — OMA + Orloj; directly relevant to the current empty-manifest handoff gap.
2. **Structural receipts for role/order plus assertion/evidence cross-check** — OMA + Agent Fleet; strengthen evidence without trusting prose.
3. **Approval CAS/content hash and human channel separated from agents** — OMA + Temporal; reduce race and autoapproval risks.
4. **Desired versus observed status; typed retry/lease/dead-letter/interruption states** — Orloj + BoundFlow + Chorus.
5. **Governance audit separated from execution traces, correlated by stable IDs** — BoundFlow; preserve evidence-grade facts separately from best-effort telemetry.
6. **Stable actor/session/provider-resume identity separation** — Chorus + GitMesh adapter codecs.
7. **Default-deny/tool-surface reduction with explicit enforcement level** — OMA + Agent Fleet; requires host enforcement, not prompt-only configuration.
8. **Atomic work claim, queue/backpressure and reconciliation** — Mission Control + BoundFlow + GitMesh.
9. **Per-run derived evidence archive plus context/drift/budget envelopes** — Agent Fleet; derived files must not replace authoritative ACI/APT facts.
10. **Cryptographic event attestation** — Mission Control + GitMesh; useful only with scoped claims, key management and an atomic authoritative write path.

Global blockers before code adoption: Cyberalchemy has no selected recipient license; Chorus is AGPL-3.0, Orloj/GitMesh/BoundFlow backend are Apache-2.0, and the other named repositories are MIT in the inspected revisions. Research supports patterns and follow-up adoption packets, not copying code or changing the target model.
